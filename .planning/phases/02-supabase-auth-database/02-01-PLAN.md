# Plan 02-01: Supabase SSR Client Architecture & Token Security Utilities

## Objective
Implement Next.js 15 cookie-based Supabase client helpers (`browser`, `server`, and `admin`), session middleware, and AES-256 token encryption/decryption utilities for securing social media OAuth refresh tokens.

## Context
- Uses `@supabase/ssr` and `@supabase/supabase-js`.
- Next.js 15 requires awaiting `cookies()` in server contexts.
- OAuth refresh tokens stored in `social_accounts` must be encrypted at rest using AES-256-GCM.

## Tasks

- [ ] **Task 1: Build Browser Client Helper**
  - Create `src/lib/supabase/client.ts` using `createBrowserClient` with `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`.

- [ ] **Task 2: Build Server Client Helper**
  - Create `src/lib/supabase/server.ts` using `createServerClient` with async `cookies()` supporting `getAll` and `setAll`.

- [ ] **Task 3: Build Admin Client Helper**
  - Create `src/lib/supabase/admin.ts` using `createClient` with `SUPABASE_SERVICE_ROLE_KEY` for server-side trusted operations.

- [ ] **Task 4: Build Token Encryption Utility**
  - Create `src/lib/crypto.ts` with AES-256-GCM encryption and decryption functions for OAuth access and refresh tokens.

- [ ] **Task 5: Setup Session Middleware**
  - Create `src/middleware.ts` to refresh Supabase auth cookies and protect routes (`/dashboard`, `/channels`, `/upload`, `/history`), redirecting unauthenticated users to `/login`.

## Verification Criteria
- [ ] TypeScript compilation passes with strict typing on all Supabase client methods.
- [ ] Unit check on `src/lib/crypto.ts` encrypts and decrypts test strings identically.
