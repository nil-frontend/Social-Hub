# Plan 02-02: Multi-Account Database Schema, Migrations & RLS Policies

## Objective
Author the complete PostgreSQL database schema and SQL migrations in `supabase/migrations/` for profiles, multi-account social connections, video drafts, and publishing task telemetry, protected with strict Row Level Security (RLS).

## Context
- Supports multiple YouTube accounts per user in V1 and scales to Facebook and Instagram in V2.
- Provides a ready-to-run SQL file that the user can run in their Supabase SQL Editor.

## Tasks

- [ ] **Task 1: Design Schema & Migrations File**
  - Create `supabase/migrations/20261122000000_initial_schema.sql` containing:
    - `profiles` table with automatic `on_auth_user_created` trigger.
    - `social_accounts` table with polymorphic `platform` column (`youtube`, `facebook`, `instagram`), encrypted token columns, and metadata.
    - `video_drafts` table with metadata fields (title, description, tags, privacy, COPPA, thumbnail, schedule).
    - `publish_tasks` table for tracking real-time upload progress per channel.
    - Indexes for fast lookups by `user_id` and `status`.

- [ ] **Task 2: Configure Row Level Security (RLS)**
  - Enable RLS on `profiles`, `social_accounts`, `video_drafts`, and `publish_tasks`.
  - Create policies ensuring users can only read, insert, update, and delete their own records.

- [ ] **Task 3: Export TypeScript Database Types**
  - Create `src/types/database.ts` with exact TypeScript interfaces matching the Supabase schema (`Profile`, `SocialAccount`, `VideoDraft`, `PublishTask`).

- [ ] **Task 4: Create Supabase Schema Documentation**
  - Create `docs/SUPABASE_SETUP_GUIDE.md` explaining how to execute the migration in Supabase Cloud SQL Editor.

## Verification Criteria
- [ ] Migration SQL syntax is valid PostgreSQL with idempotent statements (`IF NOT EXISTS`).
- [ ] `src/types/database.ts` aligns 100% with the SQL definitions.
